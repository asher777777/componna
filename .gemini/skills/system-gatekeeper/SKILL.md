# System Gatekeeper Skill (שומר הסף של המערכת)

## תפקיד הסקיל
סקיל זה מהווה את **שומר הסף הבלתי מתפשר** של מערכת Kosun.
לפני סיום כל משימה, הוספת פיצ'ר, תיקון באג או יצירת רכיב, הסוכן **חייב להפעיל את שומר הסף** כדי להבטיח שהקוד לא מפר אף אחד מכללי היסוד של המערכת.

---

## 5 עמודי התווך ששומר הסף אוכף

### 1. ניקיון תיקיית השורש (Root Directory Hygiene)
- **איסור מוחלט על יצירת קבצים ב-Root**: שום סקריפט בדיקה, קובץ נתונים, seed, או מסמך זמני אינו מורשה להיווצר בתיקייה הראשית (`c:\comona\`).
- **מיקום סקריפטים של רכיב**: כל סקריפט השייך לרכיב ספציפי חייב להימצא אך ורק בתוך:
  `src/modules/[module-name]/scripts/`
- **קבצי Scratch זמניים**: מותרים אך ורק בתיקיית `scratch/` ואסור שיישמרו בשורש הפרויקט.

### 2. עקרון המונופול והסמכות הבלעדית (Module Monopoly)
- **סמכות אחת לכל תחום (האוטוריטות הבלעדיות במערכת)**:
  - רכיב התחברות והרשאות (`auth-portal`): הסמכות הבלעדית לניהול סשן, אימות משתמשים והרשאות.
  - רכיב הגדרות ומיתוג (`brand-dna-hub`): הסמכות הבלעדית לשפת מותג, סגנון, צבעים וערכים.
  - רכיב ה-AI (`kosai-engine` ופונקציות השרת ב-`functions/`): הסמכות הבלעדית לתקשורת עם מודלי Gemini.
  - רכיב מסד הנתונים (`db-collections-hub`): הסמכות הבלעדית לרישום קולקציות ו-seed.
  - רכיב המדיה (`media-vault` / `media-gallery-hub`): הסמכות הבלעדית להעלאת וניהול קבצי מדיה.
- **שכבת UI בלבד ברכיבי קצה**: כאשר רכיב אחר זקוק ליכולת קיימת, הוא מייצר **אך ורק את ממשק המשתמש (UI)** וצורך את היכולת דרך `useHostCapabilities().getCapability(...)`.
- **איסור שכפול**: חל איסור מוחלט לשכפל מנועי קריאה ישירים ל-Gemini או שירותי מסד נתונים עצמאיים.
- **התדרדרות חיננית (Graceful Degradation)**: אם שירות האוטוריטה אינו זמין, שגיאת רשת, או אין מפתח - הרכיב המארח **לעולם לא קורס** ומציג ממשק חלופי או הודעה ברורה.

### 3. קריאות AI ו-Gemini דרך Firebase Cloud Functions בלבד (ללא פולבאק)
- **איסור קריאות ישירות מהדפדפן**: חל איסור מוחלט על `fetch('https://generativelanguage.googleapis.com...')` מתוך קוד הלקוח/הדפדפן.
- **כל הקריאות דרך השרת**: כל פנייה ל-Gemini מבוצעת דרך Firebase Cloud Functions (שכבת `api/functionsApi.ts` ברכיב, או Cloud Function מרכזי).
- **מודלים מורשים (2026)**: אך ורק `gemini-3.8-flash`, `gemini-3.5-flash`, `gemini-3.1-pro`.
- **הצגת שגיאה ברורה ונעימה למשתמש ללא פולבאק**: אין לבצע שרשרת פולבאק (Fallback) אוטומטית בין מודלים. במקרה של שגיאה או עומס – יש לתפוס את התקלה ולהציג למשתמש הקצה הודעה נעימה, שירותית וברורה בעברית מלאה (לדוגמה: "שירות הבינה המלאכותית עמוס כעת, אנא נסה שוב בעוד מספר רגעים"), מבלי להפיל את המערכת.

### 4. סקופ טננט רב-דיירי ושאיבת נתונים בין רכיבים (Zero Flat Collections)
- **איסור קולקציות שטוחות**: חל איסור מוחלט על כתיבה או קריאה מקולקציות גלובליות שטוחות (`collection(db, 'contacts')` אסור).
- **שימוש מחייב ב-`useTenantScope()`**:
  ```typescript
  import { SYSTEM_COLLECTIONS } from '../../../core/contracts';
  import { useTenantScope } from '../../../core/tenant';

  const { getScopedCollectionRef } = useTenantScope();
  const contactsRef = getScopedCollectionRef(db, SYSTEM_COLLECTIONS.CONTACTS);
  // Yields: collection(db, 'tenants', tenantId, 'contacts')
  ```
- **חובת לימוד פרמטרים בשאיבת נתונים מרכיב אחר**: במידה ופונקציית הרכיב היא שאיבת נתונים מרכיב אחר והצגתם – **חובה לבנות את הקריאה/השאילתה אך ורק לאחר לימוד מעמיק של הפרמטרים, המבנה והשדות** שנמצאים בפועל בקולקציה של הרכיב שמייצא את הנתונים או מקבל אותם. אין לנחש שדות!
- **איסור נגיעה ב-`firestore.rules`**: חל איסור מוחלט לשנות את חוקי האבטחה ב-`firestore.rules` כדי "לפתור" שגיאות הרשאה.
- **איסור שמירת מפתחות ב-LocalStorage**: כל מפתחות ה-API נשלפים מ-`src/core/connection/tenantApiKeys.ts`.

### 5. שלמות קומפילציה (Build Verification)
- פקודת `npm run build` (או `npx tsc --noEmit`) חייבת לעבור ב-0 שגיאות טיפוס.

## נוהל הפעלת שומר הסף (Workflow)

כאשר הסוכן מסיים לפתח, לעדכן, או לתקן רכיב:

### שלב 1: הרצת הבדיקה האוטומטית
על הסוכן להריץ בטרמינל:
```bash
npm run gatekeeper
```

### שלב 2: ניתוח תוצאות ותיקון מיידי
אם אחד המבחנים נכשל (❌):
1. **אם יש קבצים בשורש**: להעביר מיד ל-`src/modules/[module]/scripts/` או ל-`scratch/` ולמחוק מהשורש.
2. **אם יש קריאות Gemini ישירות מהלקוח**: להמיר אותן לקריאות דרך `api/functionsApi.ts` או `useHostCapabilities()`.
3. **אם יש קולקציות שטוחות**: לעטוף ב-`useTenantScope()` ולהשתמש ב-`SYSTEM_COLLECTIONS`.
4. **אם יש שגיאות TypeScript**: לתקן מיד את הטיפוסים עד לקומפילציה נקייה.

### שלב 3: הפקת דו"ח צ'קליסט שומר סף (חובה בתשובה למשתמש)
על הסוכן להציג למשתמש את הדו"ח הבא בפורמט RTL מלא:

